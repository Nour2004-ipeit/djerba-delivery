The Big Picture & The Djerba Island Topology

Why does a food delivery platform need a central backend? In Djerba, four independent applications run across different devices: Customer Mobile App, Courier Driver App, Restaurant Kitchen Tablet, and the Super Admin Dashboard. They never communicate directly with one another for security, data consistency, and fraud prevention. The central engine (djerba_backend) orchestrates all computations, state changes, and money flows.

The Unique Geographical Challenge of Djerba Island

Domain Reality
📍 Zero Postal Addresses
Outside Houmt Souk and Midoun, homes and beach bungalows lack street numbers and zip codes. The backend must rely entirely on high-precision latitude and longitude GPS coordinates attached to each order record.
💵 Cash on Delivery (COD) Splitting
Customers pay cash to the courier upon delivery (e.g., 34.500 TND). The backend tracks a virtual wallet: 85% to the restaurant, flat delivery fee to the driver, and 15% commission to the platform.
🔒 The Single Source of Truth Rule
Frontends are strictly presentation displays. They cannot calculate totals, alter order status directly, or query each other. Every single state change is sent to djerba_backend, where prices are verified against disk storage, identity is validated, and updates are committed atomically.

Core Runtime & Language (Node.js & TypeScript)

What engine actually reads and runs the backend code? How do we prevent runtime type crashes and calculation errors when processing real money?

N

Tool 1: Node.js (V8 Execution Runtime)

Foundation Runtime
💡 What It Is From Scratch
CPUs only understand binary 0s and 1s. A programming language is just plain text. To execute it, you need a Runtime Environment. In 2009, Ryan Dahl extracted Google Chrome's V8 engine into a standalone operating system program named Node.js, unlocking JavaScript on servers.
⚙️ How It Works Internally
Legacy servers (Apache/PHP) create a heavy operating system thread for every user, blocking while waiting for disk reads. Node.js uses a Single-Threaded Event Loop with Non-Blocking Asynchronous I/O via libuv, delegating disk and network reads to the OS and continuing without pausing.
🎯 Why We Chose It for Djerba Delivery
A delivery platform spends 95% of its time waiting on I/O (database writes, GPS pings, push notifications). Node.js handles thousands of concurrent connections with low RAM footprint. Furthermore, it allows sharing TypeScript types and data models across the entire stack.
TS

Tool 2: TypeScript 5 (Compile-Time Type Armor)

Language
💡 What It Is From Scratch
JavaScript is loosely typed: a variable can change types unexpectedly. In JavaScript, 4.500 + "10" = "4.50010" instead of 14.500 TND! TypeScript adds strict compile-time types that prevent type coercion bugs.
⚙️ How It Works Internally
TypeScript verifies every variable, function argument, and database record before code ever runs. If a price is assigned text, compilation halts immediately. At release, all types are stripped away, emitting pure, fast JavaScript: TypeScript incurs 0ms of runtime overhead.

export type Order = typeof orders.$inferSelect; // Strict type inferred from SQL table!
// If a developer attempts to assign order.totalAmount = "Free", TypeScript blocks the build immediately!

The Server Framework & Micro-Routing Layer

How do HTTP network requests from customer and courier smartphones reach the right function on our server? Here we dissect the hosting framework and the sub-millisecond routing engine.

N16

Tool 3: Next.js 16 (The Production Host & Compiler)

Host Framework
💡 What It Is & What Problem It Solves
To build a production Node.js backend from scratch, you must configure a compiler (SWC/Webpack), a development reloader (Nodemon), production bundling, and environment variable loaders. Next.js 16 provides all of this out-of-the-box in a single cohesive engine.
⚙️ How It Works in Our Project
Next.js features an App Router. Instead of writing fragmented individual endpoints, we create a catch-all wildcard route src/app/api/[[...route]]/route.ts. Next.js captures all HTTP requests beginning with /api/* and delegates execution directly to Hono.
File: djerba_backend/src/app/api/[[...route]]/route.ts The Wildcard Delegation Bridge
import { handle } from 'hono/vercel';
import { Hono } from 'hono';
const app = new Hono().basePath('/api');
// Next.js delegates all HTTP verbs directly to Hono:
export const GET = handle(app);
export const POST = handle(app);
export const PUT = handle(app);
H4

Tool 4: Hono 4 (Ultra-Fast Web Standards Micro-Router)

API Micro-Router
💡 Why Not Express.js?
Express.js was designed in 2010 around legacy Node.js callbacks. Its routing mechanism relies on slow string manipulations (adding 10–15ms of latency). Hono 4 is built on modern Web Standards (Request, Response, Fetch API) and routes requests in under 1 millisecond using an optimized RegExp tree router.
⚙️ Features in Djerba Backend
1. Global CORS Middleware: Allows all 4 Flutter frontends (ports 8080 to 8086) to communicate with the server without browser security blocks.
2. Type-Safe RPC: Exports export type AppType = typeof routes; so clients have complete compile-time type safety over the API.
File: djerba_backend/src/app/api/[[...route]]/route.ts Hono Router Tree & CORS
app.use('*', cors({
  origin: (origin) => origin, // Allows Flutter Web apps on localhost:8080..8083
  credentials: true,
  allowHeaders: ['Content-Type', 'Authorization', 'Accept'],
}));
const routes = app
  .route('/auth', authRoute)
  .route('/orders', ordersRoute)
  .route('/drivers', driversRoute);
⚡ Latency Benchmark: Hono vs Express
When a customer in Djerba taps "Commander", Hono resolves the destination route in 0.38 milliseconds. Express takes 7.4 milliseconds. In high-concurrency dispatch scenarios (dozens of drivers polling GPS simultaneously), Hono preserves server resources and prevents request queuing.

Identity, Multi-Role RBAC & Data Gatekeeping

How do we ensure that a driver cannot accept an order on behalf of another driver? How do we prevent a customer from injecting a negative meal price?

BA

Tool 5: Better-Auth (Authentication, Sessions & RBAC)

Security Suite
💡 What It Is From Scratch
Better-Auth is a TypeScript-first authentication suite. It handles user sign-ups, cryptographic password hashing (bcrypt), bearer session generation, and Role-Based Access Control (RBAC). It stores credentials directly in our database—giving us 100% data ownership with zero third-party lock-in.
⚙️ How It Works in Our Mobile Apps
Mobile apps (Flutter) do not use browser cookies. Better-Auth's bearer() plugin extracts the session token from the standard Authorization: Bearer <token> header. Our custom requireAuth(['client']) middleware verifies user roles before allowing access to any sensitive endpoint.
File: djerba_backend/src/server/auth.ts Better-Auth Multi-Role Configuration
export const auth = betterAuth({
  database: drizzleAdapter(db, { provider: "sqlite", schema }),
  user: {
    additionalFields: {
      role: { type: "string", defaultValue: "client" }, // Roles: client, driver, restaurant_admin, admin
      phoneNumber: { type: "string" }
    }
  },
  plugins: [ bearer(), phoneNumber({ otpLength: 4 }), emailOTP({ otpLength: 4 }) ]
});

Tool 6: Zod & @hono/zod-validator (The Data Firewall)

Input Validator
💡 Compile-Time vs Runtime Safety
TypeScript only exists at compile time. Once the server runs, raw JSON arriving over the network could contain anything: missing fields, negative numbers, or malicious SQL commands. Zod provides runtime schema validation to inspect payloads before they reach business logic.
⚙️ How It Works in Our Backend
The @hono/zod-validator middleware sits in front of routes. If a customer sends "quantity": -2 or "deliveryLat": "beach", Zod rejects the request with HTTP 400 Bad Request, shielding the database from corrupted data.

Where are orders, restaurant menus, and user accounts permanently saved? How do we prevent SQL injection vulnerabilities while maintaining sub-millisecond database queries?

SQL

Tool 7: SQLite & LibSQL (The Zero-Latency ACID Vault)

Database Engine
💡 What It Is From Scratch
Unlike MySQL or PostgreSQL which require running separate server processes that communicate over a network port (introducing 10–30ms network round-trip latency), SQLite is an embedded database engine that reads and writes directly to a single local file (sqlite.db).
⚙️ ACID Guarantees & LibSQL
SQLite provides full ACID reliability: Atomicity, Consistency, Isolation, and Durability. LibSQL (by Turso) modernizes SQLite with support for cloud replication, enabling effortless transitions from local files to distributed edge deployments.
File: djerba_backend/src/db/index.ts LibSQL Client Initialization

import { createClient } from '@libsql/client';

  url: process.env.TURSO_URL ?? 'file:sqlite.db', // Local zero-latency disk file
  authToken: process.env.TURSO_AUTH_TOKEN,
});
export const db = drizzle(client, { schema });
DR

Tool 8: Drizzle ORM (TypeScript-to-SQL Translator)

ORM Translator
💡 Why Not Prisma?
Prisma relies on an external Rust binary engine that parses queries through a separate runtime layer, increasing memory usage and startup times. Drizzle ORM has zero runtime overhead—it compiles TypeScript directly into standard SQL queries with native type inference.
⚙️ Crucial Design: Price Snapshotting
If a restaurant changes a couscous price from 18 TND to 22 TND tomorrow, past orders must still record that the customer originally paid 18 TND. Drizzle's order_items schema preserves historical data by snapshotting unit prices and dish names at checkout.

In-Memory RAM, Geospatial Dispatch & Mutex Locks

What happens when two couriers tap "Accept" on the same delivery run at the exact same millisecond? How does the server track live scooter coordinates without wearing down the database?

R

Tool 9: Upstash Redis (In-Memory Key-Value & Geospatial Store)

In-Memory Store
💡 The Courier Race Condition Problem
When an order is marked ready for pickup, multiple couriers nearby receive the alert simultaneously. If Driver A and Driver B tap "Accept" at the exact same moment, standard database queries can both read status == 'pending', resulting in both drivers showing up at the restaurant.
⚙️ The Solution: Atomic Mutex Lock
Redis executes in-memory operations sequentially on a single thread. We use the atomic command: SET lock:order:{id} driverId NX EX 10.
• NX (Not eXists): Succeeds only for the first request; fails immediately for the second.
• EX 10: Automatically expires the lock after 10 seconds if the driver loses connectivity.
File: djerba_backend/src/server/services/dispatch.ts Redis Mutex Lock & Geospatial Engine
export class DispatchService {
  // 1. Atomic Distributed Mutex Lock:
  static async lockOrder(orderId: string, driverId: string): Promise<boolean> {
    const acquired = await redis.set(`lock:order:${orderId}`, driverId, { nx: true, ex: 10 });
    return acquired !== null; // True = acquired! False = another courier was faster!
  }

  // 2. High-Frequency Live GPS Tracking (Saved in RAM, not disk):
  static async updateDriverLocation(driverId: string, lat: number, lng: number) {
    await redis.geoadd('active_drivers', { longitude: lng, latitude: lat, member: driverId });
    await redis.setex(`driver_last_seen:${driverId}`, 300, Date.now().toString());
  }
}
⚠️ Why Upstash Redis Over Traditional Redis?
Traditional Redis maintains persistent TCP socket connections, which can be unstable in serverless or edge environments. Upstash Redis communicates over stateless HTTP REST calls, making it resilient to container restarts and scaling seamlessly without socket connection limits.

Tool 10: Firebase Admin & Cloud Messaging (FCM)

Push Notifications
💡 The Mobile Sleep Problem
Mobile operating systems (iOS and Android) actively preserve battery by closing background socket connections. When a customer places an order, the kitchen tablet screen may be asleep and drivers may have their phones locked in their pockets. Standard HTTP requests cannot reach idle devices.
⚙️ How FCM Solves It
Firebase Cloud Messaging connects with Apple's APNs and Google Play Services to deliver high-priority push payloads directly to the device hardware, waking the screen and playing alert tones even if the application is closed.

SMTP Mailer

Nodemailer manages encrypted TLS/SMTP handshakes with mail providers (e.g., Gmail) to deliver account verification and password reset OTPs.

The Complete Lifecycle of a Djerba Order

Here is how every tool in the backend cooperates chronologically from the moment a customer orders a meal in Midoun to final cash collection:

Stage Tool Active Technical Operation What Happens Under the Hood
1. Network Next.js 16 + Hono 4 POST /api/orders The customer's Flutter app sends an HTTP POST request. Hono evaluates route patterns in under 1 millisecond.
2. Identity Better-Auth requireAuth(['client']) Verifies the Bearer token against active database sessions and confirms the caller holds the client role.
3. Guard Zod zValidator('json', ...) Validates that item quantities are positive integers and GPS coordinates are valid floats before proceeding.
4. Persist Drizzle + SQLite db.transaction(...) Queries verified menu prices from disk, calculates the total, and writes both the order and item snapshots in an atomic transaction.
5. Notify Firebase FCM sendNotificationToUser(...) Dispatches a high-priority push message to wake up the restaurant kitchen tablet and sound the order chime.
6. Claim Upstash Redis SET lock:order:{id} NX EX 10 Multiple drivers tap "Accept". Redis awards the atomic lock to the first request and returns an error to subsequent drivers, preventing duplicate assignments.
7. Track Redis GEOADD updateDriverLocation(...) The courier's phone sends GPS updates every 3 seconds to in-memory RAM, enabling live tracking without exhausting disk I/O.
8. Settle SQLite (djerba.db) status = 'delivered' The driver collects cash (e.g., 34.500 TND). SQLite updates the order status and credits the driver's balance, tracking the 15% platform commission.
