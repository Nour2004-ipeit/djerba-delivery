01. Core Computing Fundamentals (From Scratch)

1. What is a Programming Language?

A programming language is a structured vocabulary and grammar that humans use to write instructions for computers. In our project, we use 3 distinct languages:
• Dart: Google's language used to paint visual buttons, maps, and screens on phones (Flutter).
• TypeScript / JavaScript: The mathematical calculation language used on our backend server.
• SQL (Structured Query Language): The universal database language used to fetch and store records.

2. JavaScript (JS) vs. TypeScript (TS) — Why Do Both Exist?

📜 JavaScript (JS): The Flexible Pioneer

Created in 1995, JS has no strict data types. You can put numbers into a text variable without warning. While fast to write, silly typos and type errors crash the application in front of real users.

🛡️ TypeScript (TS): JavaScript with Armor

Created by Microsoft, TypeScript adds strict Types (e.g. price: number). If you attempt to assign text to a price, the compiler highlights it in red and refuses to build, catching bugs before release!

3. What is Node.js and What is a "Runtime / Environment"?

A language is just text. To execute it, you need a Runtime Environment—a software engine that reads lines of code and translates them into CPU machine instructions (1s and 0s).
• The Historical Constraint (1995–2009): JavaScript could ONLY run inside web browsers (Chrome, Firefox). It could only animate HTML buttons. It was completely forbidden from touching files or databases.
• The Node.js Breakthrough (2009): Ryan Dahl extracted Google Chrome's V8 engine into a standalone computer program called Node.js.
• The Result: JavaScript gained the ability to run on Windows/Linux servers, query databases, read disk files, and listen on network ports. Today, TypeScript/Node.js powers server infrastructure at Netflix, Uber, PayPal, and Airbnb!

4. What are Environment Variables (.env)?

Your server needs secret credentials (database passwords, SMS API keys, session tokens). You must never write passwords directly in code files because publishing code to GitHub would expose them to hackers. Instead, your server reads a hidden file named .env (short for Environment) on startup. The values stay safely in computer memory.

5. Framework vs. Library: What's the Difference?

💡 The Toolbox vs. The House

• A Library (Toolbox): A specific tool you call when you need it (e.g., Dio for HTTP requests, Zod for validation). You remain in full control of your application flow.
• A Framework (House): A pre-built structure with strict architectural rules (e.g., Flutter for mobile, Next.js for servers). The framework controls the execution flow; you simply write your code in designated folders.

6. What is an API (Application Programming Interface)?

An API is a digital waiter connecting separate software applications.
When you sit at a restaurant (the Client Mobile App), you cannot walk into the kitchen yourself (security reasons!). Instead, you give your order to the Waiter (the API). The waiter carries the order to the chef (the Backend Server & Database) and brings your food back.

7. The Universal Language Rule: Why Dart + TypeScript?

The mobile app (written in Dart) and the backend (written in TypeScript) do NOT need the same language! They communicate across the internet using JSON (JavaScript Object Notation)—plain text formatted like: {"meal": "Couscous", "price": 18.500, "lat": 33.8869}. Both Dart and TypeScript read and write JSON natively!
